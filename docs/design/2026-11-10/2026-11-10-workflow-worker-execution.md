# 工作流 worker 与远端执行

日期：2026-11-10

用户已确认新增 worker 作用域，并要求在本机 WSL 完成真实 Docker/Ray 验证。本篇补充前一篇实施设计，不改变小内核、声明式步骤、独立资源、模板入口及删除旧执行路径的目标。

## 执行边界

- run 资源只在协调进程中创建，不复制进程内对象到远端。
- worker 资源由执行进程创建并拥有；生命周期内使用固定配置，跨样例复用的提供者必须显式声明安全共享。
- attempt 资源只属于当前执行尝试，重试重新创建。block/step 保留原有短期作用域。
- 远端派发使用计划、具名 JSON 绑定、执行身份和产物引用，不序列化函数、客户端或资源句柄。工作节点加载本地安装的插件，检查版本和包摘要。
- 资源创建、产物保存和结果提交保留所有权、清理和来源检查。远端未确认清理的 attempt 不自动重放。
- 默认仍使用本地后端，用户通过模板和调度配置选择 Ray；不要求普通使用者手写资源作用域。

## 实施及验收

先实现本地 worker 生命周期和边界校验，再接入可序列化单元执行及 Ray，随后迁移 Benchmark、旧入口、配置和 Playbook。真实验证使用 WSL 中可用的 Docker 与隔离的测试运行环境；模型服务使用受控请求验证流程行为，不把它记为真实模型评分验收。

## 已确认的 Ray 连接所有权补充

用户随后明确选择共用 ray.connection 资源。当前原 RayScheduler 与新 executor.ray 都会启动驱动与 HTTPS 服务，无法直接共享准备节点及同一个固定接收端口。

新增 ray.connection，由它启动和释放 Python 驱动、HTTPS 服务，按运行/attempt 身份路由控制请求。原 RayScheduler 在工作流准备场景中借用连接，新 executor.ray 也借用同一连接；两者释放自身状态时不关闭借用的连接。恢复操作可以短期开启独立连接，因为原运行的连接已经退出。

模板生成连接、执行器及 Benchmark 资源之间的依赖，用户仍只配置一份 scheduler。保留原准备器的批量准备、节点分配和准备回执，随后把实际评测派发到已准备的节点，由通用步骤执行器运行。核心内核不按 Benchmark 名称或类别分支。

## 已确认的补测输入身份

用户确认区分业务输入指纹与本次派发参数。WorkflowAdmission 可通过 reuseInputs 声明决定结果复用的稳定输入；Benchmark 包含锁定来源、题目引用、实验配置指纹和 Solver 来源。内核另外保留样例、模型分组和重复次数，不将本次准备回执当作业务变化。未声明该方法的插件继续比较原有完整输入。

WorkflowUnitRequest 单独记录 dispatchFingerprint，校验全部传输绑定及业务输入指纹。节点身份仍由 Ray 路由信封检查；计划与插件版本继续单独校验。改变准备轮次或 artifact ID 不应使已成功的 Benchmark 单元重跑，但实际题目、配置或来源变化仍须拒绝复用。

## 已确认的远端凭据读取

用户确认保留只在提交端配置模型认证的用法。ResourceProvider 声明配置所需的环境变量名称；运行时凭据读取支持异步解析，节点已有配置优先，缺少时经现有认证 HTTPS 通道按需获取。凭据值只保存在内存中，不进入计划、派发恢复身份、结果或节点 request.json。新增读取值必须同时进入当前 worker 的日志脱敏集合。

协调端按已锁定计划、当前模型分组与资源声明确定本次派发允许读取的名称，拒绝未声明名称。只传名称引用作为恢复所需信息；恢复操作重新解析凭据。Benchmark 的远端 attempt 显式声明从模板服务配置提取的名称，不能根据题目私有内容请求任意环境变量。动态步骤输出不能自行扩大凭据允许列表。

## 已确认的 Jobs 凭据与续跑传输

用户确认修改 Jobs 网关：凭据只存网关内存，协调进程按需读取；不再把认证放入 input.json 或 retry-auth 文件。网关重启后需重新提供凭据。续跑上传完整文件和产物，分块传输并校验大小、摘要、路径；不能继续使用只有原生结果元数据的 seed。普通运行和续跑命令保持简洁，由应用层处理上传、部署、跟随和结果下载。
