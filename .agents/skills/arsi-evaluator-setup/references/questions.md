# 分批问题清单

先完成 `benchmark list`、`benchmark info <name>` 和 `init`，把 Profile 已经确定的字段写成“已确认”，再只问下表中仍缺失或需要用户决策的项。访谈分三轮：三项必选 → 可选项开关 →（仅开关选择“需要配置”时）关键可选项。每轮最多 5 个问题。

## 提问格式

问句使用简洁、规范的书面语，一句话说明需要用户决定的事项。标签仅出现在 header，默认值、示例与限制条件写在选项描述中；每轮在正文最多给一次命令提示。

```text
问：选择要评估的 Benchmark。
选项：gsm8k（轻量数学推理，适合验证链路）／aisbench／deepswe／terminalbench／其他
提示：可运行 arsi-evaluator benchmark list 查看全部候选。

问：Harness 采用默认配置，还是指定其他实现？
选项：使用默认（推荐）／指定其他实现
```

表达规范：

- 使用书面语与准确术语，不使用口语化表达（如“跑几道题”“同时跑几个”“都按默认”）。
- 不将标签、命令或“默认：无，必须由你提供”等模板句写入问句。
- 每个必选问题给出“比如 <名称>”的示例，并说明可用哪个命令查询更多信息。
- 字段名可以出现，但需附中文说明，例如“运行任务数量（`run.maxTasks`）”。

判断规则：

- **必选**：缺失会导致配置校验失败，或无法确定评测对象（Benchmark、Harness、模型名称与 API 地址）。
- **运行时必填**：配置可生成，但执行时需要能解析出值，例如 API key 的环境变量名。
- **条件必填**：仅所选 Benchmark 或场景需要，例如独立裁判服务、`HF_TOKEN`、SSH 凭据。
- **可选**：有默认值；用户选择“采用默认值”时全部保留默认。

## 第 1 轮：三项必选（一次问完）

| 问题 | 标签 | 默认/推荐 | 说明与示例 |
| --- | --- | --- | --- |
| 选择要评估的 Benchmark。 | 必选 | 从 `benchmark list` 推荐与目标最接近的项 | 比如 `gsm8k`、`terminalbench`；选项给出名称与一句话定位。更多候选通过 `arsi-evaluator benchmark list` 查询，细节通过 `benchmark info <name>` 查询。 |
| Harness 采用默认配置，还是指定其他实现？ | 必选 | 该 Benchmark 的默认 Harness | 比如 gsm8k 默认 `simpleagent`；选择指定时收集名称，例如 `trae`、`codex`，并校验该 Benchmark 是否支持。 |
| 配置模型服务：模型名称与 API 地址。 | 必选 | 无 | 比如 `your-model` + `https://api.example.com/v1`。密钥仅收集环境变量名，默认 `MODEL_API_KEY`；条件必填项（独立裁判、`HF_TOKEN`、SSH 凭据）随本项一并询问。 |

执行要点：

- 三项必选在同一轮完成，不拆分为多轮重复追问。
- 用户未提供模型名称或 API 地址时配置无法生成，必须等待用户给出。
- 版本与场景默认使用 Profile 的 `defaultVersion` / `defaultScenario`，用户主动要求时才修改。

## 第 2 轮：可选项开关

| 问题 | 标签 | 默认/推荐 | 说明与示例 |
| --- | --- | --- | --- |
| 是否配置可选项（运行任务数量、并发度、执行环境等）？ | 可选 | 采用默认值 | 选项为“采用默认值（推荐）/需要配置”。选择采用默认值后直接生成 YAML，不再询问其他项。 |

执行要点：

- 该问题必须询问一次，不得跳过直接询问任务数量或并发度。
- 选择“采用默认值”时，在最终摘要中注明“可选项均采用默认值”。

## 第 3 轮：关键可选项（仅当第 2 轮选择“需要配置”时）

| 问题 | 标签 | 默认/推荐 | 说明与示例 |
| --- | --- | --- | --- |
| 运行任务数量。 | 可选 | 全部；首次建议 2～10 条 | 写入 `run.maxTasks`；AISBench 的一次运行对应一个测量点（默认 160 条请求）。 |
| 并发度。 | 可选 | 1 | 写入 `scheduler.concurrency`；并发受本机资源与模型服务限流影响。 |
| 是否还有其他默认项需要修改？ | 可选 | 不需要 | 用户点名后再修改输出目录、超时、执行环境等具体项。 |

执行要点：

- 只询问用户真正会关心的项，不逐项确认 `hardware`、`store`、`reporter` 等。
- 第 2 轮选择“采用默认值”时整轮跳过，包括“是否还有其他默认项需要修改”。
- 并发在未确认宿主机资源时不承诺“安全并发”；并发是上限，不是容量承诺。

## 不要问的字段

以下字段有默认值或由 Profile 管理，除非用户明确提出需求，否则不要逐项追问：

- `store`、`reporter`、`metrics` 的实现细节。
- Profile 已提供的 Benchmark 数据来源、版本、场景、验证器和默认预算。
- 内部执行参数、缓存路径、容器工作目录、日志级别。
- Ray 的集群内部细节；只有用户选择 Ray 时才确认连接和节点。
- 任何密钥、token、代理密码的真实值。

## 访谈结束前的自检

- [ ] 三项必选（Benchmark、Harness、模型服务）均已确认，问句使用规范书面语。
- [ ] 第 2 轮可选项开关已询问；选择“采用默认值”时未追问其他项。
- [ ] 所有 `[条件必填]` 项已确认。
- [ ] YAML 中的认证字段全部是 `${ENV_NAME}` 引用。
- [ ] 已经说明下一步将执行 `inspect` 和 `doctor`，以及 doctor 可能产生下载或构建探针。
